Q2

아이디어를 떠올린 배경

스마트팩토리 도입의 가장 큰 장벽은 최하단 장비(L0) 영역의 폐쇄성입니다. 현재 제조 현장은 특정 벤더의 고가 전용 하드웨어와 무거운 레거시 소프트웨어에 종속되어 있습니다. 현장 엔지니어들은 새로운 장비를 연동할 때마다 수천 개의 메모리 주소를 엑셀로 일일이 매핑하고 수동 코딩하는 소모적인 작업을 반복해야 합니다.

이러한 막대한 도입 비용과 개발 시간의 낭비를 보며, "오픈 소스 하드웨어(라즈베리파이) 위에 제어 로직, 최신 웹 기반 모니터링(HMI), 그리고 모든 산업용 프로토콜을 변환하는 게이트웨이를 하나의 소프트웨어로 통합"한다면 중소·중견 제조기업의 디지털 전환(DX) 진입 장벽을 완전히 허물 수 있다고 확신했습니다.

핵심 인사이트: Moru의 초기 타겟(스마트팜·IIoT·로보틱스)은 기성 벤더가 장악하지 않은 그린필드 시장입니다. 전환할 레거시가 없고, 신기술에 개방적이며, 인증 부담이 낮은 이 세 시장에서 레퍼런스를 빠르게 쌓은 뒤, 기술 성숙도에 따라 상위 시장으로 확장하는 Land & Expand 전략입니다.

(2) 엔진 교체 + 아키텍처 슬림화 — 두 가지 모드

창업 지원을 통해 검증된 아키텍처의 제어 엔진을 Rust 기반 런타임(moru-runtime)으로 교체하고, 전체 통합 소프트웨어를 RevPi 기반 '플러그 앤 플레이형 엣지 어플라이언스'로 패키징합니다. 단순한 엔진 교체를 넘어 Rust 네이티브 스택의 장점을 살려 레이어를 의도적으로 단순화합니다:

모드 A — Rust Native / MQTT-first [기본값]

Rust 런타임이 rumqttc 크레이트로 MQTT 브로커와 직접 통신. Python FastAPI 게이트웨이 레이어가 불필요하게 제거되어 지연(latency), 메모리 풋프린트, 배포 복잡도가 모두 감소합니다. 현대 IIoT 장비에 바로 붙는 가장 슬림한 경로.

RevPi → rumqttc → MQTT Broker → Cloud/HMI

모드 B — Legacy Bridge / Universal Adapter [옵션]

Modbus TCP, Hostlink(OMRON), EtherCAT, Profinet, OPC-UA 같은 레거시 프로토콜만 지원하는 구형 PLC가 있을 때 Gateway가 Universal Adapter로 전환. 여러 레거시 프로토콜을 MQTT로 정규화합니다. axum 기반 Rust 구현의 선택적(optional) 컨테이너.

Legacy PLC → axum Bridge → MQTT → Cloud/HMI

Land & Expand: 이 두 모드 구조는 "벤더 종속성 파괴"라는 핵심 가치와 정확히 정합합니다. 고객사는 먼저 레거시 장비에 Bridge 모드(B)로 진입하여 데이터 수집·모니터링에서 신뢰를 쌓고, 이후 신규 라인 증설 시 Native 모드(A)로 이행하는 자연스러운 확장 경로가 기술 구조상 보장됩니다.

(3) 5중 안전망 — AI 코드가 현장에서 안전하게 동작하는 근거

01
Rust 컴파일 하네스

Rust의 소유권(Ownership)·대여 검사기(Borrow Checker)·수명(Lifetime) 규칙을 컴파일 단계에서 강제하여 메모리 누수, 데이터 레이스, 널 포인터 역참조 같은 시스템 레벨 결함을 원천 차단합니다. "컴파일을 통과하면 메모리/동시성 측면에서는 현장에서도 무조건 동작한다"는 강력한 보증.

02
BDD 기반 e2e Verification

Rust 컴파일러가 시스템 결함을 차단하더라도 "닫아야 할 밸브를 열라고 지시"하는 논리적 결함(Logic Error)은 잡아내지 못합니다. 요구사항에서 자동 도출한 BDD 시나리오로 가상 환경에서 e2e 테스트를 실행하여, 시스템의 기대 거동과 실제 거동 일치를 구조적으로 Verification합니다.

03
Human-in-the-Loop 최종 승인

현장 엔지니어가 웹 HMI에서 직접 Verification 결과를 확인하고 승인한 경우에만 실 하드웨어에 배포됩니다. AI가 아무리 자신감을 가져도, 최종 게이트키퍼는 사람입니다. 이 철학은 플랫폼 아키텍처에 내장되어 우회 불가.

요약: "Infrastructure 조립 범위 제한 + Rust 컴파일 + Kanban Self-Healing + BDD e2e Verification + Human Approval" — 5중 안전망이 LLM 환각의 논리적 결함까지 구조적으로 차단합니다.

(4) 최종 비전

"요구사항만 말하면 즉시 동작하는 제어기" → 누구나 쉽고 저렴하게 공장을 스마트화할 수 있는 '구독형(SaaS) 스마트팩토리 인프라 표준'으로 스케일업. 고가의 전용 PLC 시스템(라인당 $150K–$500K)을 라즈베리파이 어플라이언스 + SaaS 구독 모델로 대체하고, 단순 1회성 구축(SI)의 한계를 넘어 글로벌 B2B 솔루션으로 성장합니다.

시연 자산이 이미 브라우저 URL로 가동 중이라는 점은, 창업 지원 심사 → 초기 고객 PoC → Pre-A 투자 IR까지 이어지는 모든 단계에서 "개념 제안"이 아닌 "실물 데모"로 승부할 수 있는 결정적 차별점이 됩니다.

Red Team Defense

심사위원의 공격을
미리 파훼한다

보수적인 제조 현장의 현실을 고려할 때 심사위원으로부터 받을 수 있는 치명적 공격 포인트 4가지와, 각각에 대한 구조적 방어 논리입니다.

01

"라즈베리파이요? 공장 현장을 너무 우습게 보시는 거 아닙니까?"

극한 환경에서 수천만 원짜리 전용 PLC를 쓰는 이유는 '신뢰성' — 장난감 같은 보드로 공장을 돌린다고?
산업용 인증 RevPi 폼팩터

일반 라즈베리파이가 아닌 산업용 인증(KC, CE, EN 61131-2) 딘레일 마운트 폼팩터인 RevPi(KUNBUS) 사용. RevPi Connect 5(CM5)는 2.4GHz 쿼드코어 + PCIe Gen 3 + 산업용 온도 범위를 지원하는 진짜 산업용 엣지 PC.

소프트웨어가 핵심 경쟁력

핵심 경쟁력은 하드웨어 제조가 아니라 '오픈 아키텍처 위에 올라가는 소프트웨어와 AI 최적화'에 있음. 하드웨어는 교체 가능한 범용 레이어, 지적재산은 소프트웨어 스택에 집중.

파훼 한줄: "라즈베리파이는 장난감이다"는 2018년식 반론. 2026년의 CM5 + 메인라인 PREEMPT_RT + Rust(GC-free) 3층 결정론적 스택 앞에서 더 이상 유효하지 않습니다.

02

"AI가 밸브를 반대로 열면? 사람이 다치면 누가 책임집니까?"

Rust가 메모리 에러는 잡지만 논리적 결함까지는? 미션 크리티컬 제어에 AI 코드를 바로 꽂는 건 위험.
1단계 진입 전략 — 스코프 한정

초기에는 메인 설비(L0) 제어에 바로 개입하지 않고, 리스크가 적은 데이터 수집(Gateway) 및 모니터링(HMI), 서브 팹 보조 설비 제어부터 적용합니다. 레거시 PLC 시장의 "오버킬 화이트스페이스"에서 먼저 가치를 증명합니다.

3중 안전망 — 구조적 방어
LAYER 1: COMPILE

Rust Ownership + Borrow Checker → 메모리/동시성 결함 컴파일 단계 원천 차단

LAYER 2: TWIN

수천 가상 시나리오 자동 시운전 → 논리적 결함 사전 검출

LAYER 3: HUMAN

엔지니어 웹 HMI 승인 → AI 우회 불가, 최종 게이트키퍼는 사람

03

"고객이 보수적이라 스타트업 제품 안 씁니다" — 타겟 재설정으로 구조적 해결

이 공격은 석유화학·중공업에는 유효하지만, Moru의 초기 타겟에는 해당하지 않습니다.
타겟 시장 자체가 그린필드 — 전환 비용이 존재하지 않는다

Moru의 초기 타겟은 교체할 레거시가 없습니다. 기성 벤더의 진입장벽이 낮고 신기술 채택 속도가 빠른 세 시장을 선택함으로써 이 공격 포인트를 구조적으로 무력화했습니다.

🌱 스마트팜 신규 설치

처음부터 오픈 하드웨어로 구성하는 그린필드 — 뜯어낼 레거시 PLC가 없습니다. 오히려 저렴하고 빠른 솔루션을 환영합니다.

📡 IIoT 스타트업

새 프로젝트를 빠르게 구현해야 하는 팀 — Moru 같은 AI 개발 도구를 적극 환영합니다. "보수적 공장장"이 아닌 "개발 속도에 민감한 CTO"가 의사결정자입니다.

🤖 로보틱스 기업

자체 제어 로직 개발에 공수가 많이 들어 AI 자동화에 가장 개방적인 집단. 개발 사이클 단축이 곧 시장 경쟁력.

결론: 보수적 대형 공장(석유화학·중공업)은 Moru의 초기 영업 대상이 아닙니다. M18+ 이후 레퍼런스를 충분히 쌓은 뒤 상위 시장으로 확장하는 단계적 접근입니다.

04

"결국 이것도 공장마다 다 맞춰줘야 하는 SI(용역) 아닙니까?"

공장마다 장비·프로토콜·UI가 다 다른데, 결국 상주 세팅이면 스케일업 불가능한 고급 외주.
Plug & Play 표준화 — 80%+ 자동 세팅

스타트업 직원이 공장에 상주하지 않아도, 고객사 엔지니어가 직접 스펙 문서를 업로드하거나 노코드/로우코드 UI에서 몇 번의 클릭만으로 80% 이상의 세팅(매핑)이 자동 완료되는 구조입니다.

STEP 1

장비 스펙 문서 업로드 → AI Agent가 통신 맵·제어 로직 자동 생성

STEP 2

Screen Editor 노코드 UI에서 HMI 화면 구성 → 드래그 앤 드롭

STEP 3

디지털 트윈 시운전 → 승인 → 원클릭 배포. 원격 완료.

SI vs SaaS 분기점: "우리가 가서 세팅해드립니다" = SI. "AI가 세팅하고 트윈에서 검증한 뒤 고객이 승인합니다" = SaaS. PoC 라이브 시연에서 이 차이를 10분 안에 증명합니다.

3대 장벽,

Moru의 비전이 실현되려면 넘어야 할 기술적·시장적·인증 장벽 3가지와, 각각에 대해 이미 확보한 파훼법입니다.

01

범용 OS의 하드 리얼타임 한계

리눅스는 결정론적 타이밍 보장 불가 — 서보/모션 제어는 어떻게?
(A) 스코프 분리 — 초기 타겟 = 소프트 RT 화이트스페이스

초기 타겟은 소프트 리얼타임 영역입니다. 펌프·밸브 제어, 데이터 수집, 감독 제어(Supervisory Control) 등 200ms 주기로 충분한 영역은 현재 레거시 PLC 시장에서 하드 RT로 오버킬되고 있는 거대한 화이트스페이스입니다. 이 영역에서 먼저 가치를 증명한 후, 하드 RT가 필요한 서보/모션 제어로 확장합니다.

(B) CM5 + 메인라인 PREEMPT_RT — 하드 RT 확장 경로
  • • Linux 커널 6.x 메인라인 PREEMPT_RT 공식 병합 — 20년간 유지된 PREEMPT_RT 패치가 드디어 리눅스 메인라인에 공식 병합. 실험적 패치가 아닌 공식 커널 기능으로 µs-레벨 최악 지연(worst-case latency) 보장.
  • • RevPi Connect 5 (CM5) — Raspberry Pi Compute Module 5 기반 산업용 컨트롤러. 2.4GHz 쿼드코어 + PCIe Gen 3 + EN 61131-2 산업용 인증. 기존 RevPi 대비 CPU 성능 3배, I/O 대역폭 대폭 향상.
  • • CM5 + PREEMPT_RT + Rust(GC-free) = 3층 결정론적 스택. 하드웨어(산업 인증) + OS(메인라인 RT) + 언어(가비지 콜렉터 없는 제로코스트 추상화)가 모두 결정론적 타이밍을 지원.

IR 포지셔닝: "소프트 RT에서 먼저 검증하고, CM5 + PREEMPT_RT로 하드 RT까지 확장합니다. 이미 하드웨어(EN 61131-2)와 커널(메인라인 RT)과 언어(Rust GC-free)가 모두 준비되어 있습니다. 기술 리스크가 아닌 실행 리스크만 남아 있고, 실행은 이미 1회 검증했습니다."

02

AI 로직 에러 — 책임 소재 & 기능 안전 인증

Rust가 메모리 에러는 막지만 논리적 결함까지는? IEC 61508 인증은?

이 장벽에 대한 방어는 7단계 구조적 방어로 구성됩니다:

1
디지털 트윈 아키텍처 — 이미 1회 완성

8개 컨테이너 풀스택 가상 공장을 단일 URL에서 운영해 본 실적. AI 코드가 실물 배포 전 수천 시나리오에서 자동 검증되는 구조.

2

03

'Rip and Replace' — 현장의 극단적 거부감

검증 안 된 스타트업 제어기를 공장에 꽂는 모험? 공장장이 허락할 리가 없다.

비침투적 트로이 목마 전략 — 기존 PLC를 건드리지 않고 IIoT 엣지 게이트웨이로 먼저 침투(Retrofitting)합니다. 아무리 SaaS 모델이 저렴해도, 24시간 돌아가야 하는 공장은 기존에 잘 돌아가는 지멘스나 미쓰비시 PLC를 뜯어내고 검증되지 않은 스타트업의 제어기를 메인으로 꽂는 모험을 절대 하지 않습니다. 이것을 전제로 설계된 GTM 전략입니다.

Phase 1: 데이터 브릿지 (Retrofitting)

기존 제어 로직을 건드리지 않고, 공장 내의 고립된 데이터를 수집해 대시보드(HMI)에 띄워주는 가벼운 브릿지 역할로 들어갑니다. 공장장의 신뢰를 얻는 것이 첫 번째 목표. Gateway Mode B(Universal Adapter)가 이 단계의 기술 기반.

Phase 2: 보조 설비 제어 (Expand)

신뢰 축적 후 리스크 적은 보조 라인(냉각수 펌프, HVAC, 유틸리티 밸브 등)부터 Moru 런타임으로 제어 영역 확장. 메인 생산 설비의 기존 PLC는 그대로 유지하면서 보조 설비만 대체.

Phase 3: 신규 라인 메인 L0 (Replace)

신규 증설 라인에 Moru를 메인 제어기로 도입. Gateway Mode A(Rust Native/MQTT-first)로 레거시 의존성 zero. Greenfield 라인에서 완전 대체를 달성하는 최종 단계.

핵심 전환 심리: "기존 시스템을 뜯어내세요" (X) → "기존 시스템은 그대로 두고, 막혀있던 데이터부터 뽑아드리겠습니다" (O). 이 한 문장이 공장장의 첫 번째 "예"를 이끌어내는 트리거.

왜 순수 성과 기반 모델이 아닌가?

순수 성과 기반(Pure Outcome-Based) 과금은 매력적이지만, 초기 스타트업에 심각한 현금 흐름 불안정성을 초래합니다 — 고객사 공정 특성, 측정 기준, 정산 주기 협상에 따라 매월 수익 편차가 5배 이상 벌어질 수 있고, 투자자의 재무 모델 예측이 거의 불가능해집니다.

가장 차별화된 부분 — 아키텍처 설계 완료, E2E 데모 진행 중

LLM + Kanban Harness 아키텍처 완성 / Kanban Harness MVP 구현 M0~2 최우선 과제

기획서의 핵심 약속은 "AI에게 말하면 제어기가 완성된다"인데, 현재 moru_repo에 AI Agent 구현체가 미완성 상태입니다. Rust 런타임은 인상적이지만, AI 코드 생성 파이프라인이 없는 Moru는 Beremiz나 OpenPLC와 본질적 차별점이 약해집니다.

아키텍처 응답: LLM + Kanban Harness

이 약점에 대한 설계 응답으로 LLM + Kanban Harness 아키텍처를 완성했습니다. LLM은 코드 생성 Worker, Kanban Board는 실행을 통제하는 State Machine — 두 역할을 분리하는 구조입니다.

[자연어 요구사항]
    ↓ Task Decomposition
[Kanban Board: TODO → DOING → VERIFY → DONE]
                      ↓ FAIL
        [오류 분석 Task 자동 생성 → LLM 수정 재생성 → 재시도]
    ↓ LLM Worker: Rust 제어 코드 생성
[cargo build] → FAIL 시 → Self-Healing Loop
    ↓
[Digital Twin 시뮬레이션] → [Human Approval] → 실 배포

02

1인 창업자 리스크

3~5명 팀의 일을 혼자 감당 — 투자자가 가장 꺼리는 구조

Rust 런타임 + AI Agent + 디지털 트윈 인프라 + 웹 HMI + 영업 + 고객 지원 + 투자 유치. 이건 최소 3~5명 팀의 일입니다. TIPS 심사에서도 "팀 구성"은 주요 평가 항목이고, 1인 창업자에 대한 리스크 할인은 현실적으로 큽니다.

기술력이 아무리 뛰어나도 한 사람이 burn out 하면 회사가 끝나는 구조는 투자자가 가장 꺼리는 형태.

대응: 제조업 영업/BD 경험이 있는 공동 창업자 확보. 기술은 충분하니 부족한 건 "팔아본 경험".

03

"사내에서 만들어 봤다" ≠ "고객에게 팔아봤다"

"만들 수 있다"는 검증됐지만, "팔 수 있다"는 전혀 검증되지 않았다

1회차 디지털 트윈은 본인이 요구사항을 깊이 이해하는 자기 조직 안에서 만든 것입니다. 외부 고객에게 팔아본 적은 없습니다. 제조업 B2B 영업 사이클은 6~18개월이고, 공장장 한 명 설득하는 데 수십 번의 미팅과 PoC가 필요합니다.

"만들 수 있다"는 검증됐지만, "팔 수 있다"는 전혀 검증되지 않았습니다. 이 간극이 스타트업의 사망 원인 1위입니다.

대응: 모두의 창업 단계에서 무료 PoC 1건이라도 확보. 아는 공장, 전 직장 네트워크 어디든. "고객이 있다"는 한 줄이 기획서 전체보다 강력합니다.
